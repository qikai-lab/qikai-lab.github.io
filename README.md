## 当前项目：ZigBee 无线环境监测系统

电池供电的传感器节点采温湿度、烟雾、光照与人体感应，经 ZigBee 协调器汇聚；
一路串口进 Ubuntu 上的 C 网关落库、出曲线、判烟雾告警、网页远程控制继电器，
另一路并联给 ESP32-S3 转成 MQTT 上云。

四层全部自己写：裸机驱动、无线组网、网关固件、C 服务端。

| 层级 | 组成 | 职责 |
| --- | --- | --- |
| 感知层 | CC2530 + DHT11 / MQ-2 / 光敏 / 人体红外 | 定时采集，本地彩屏显示，电池供电 |
| 汇聚层 | CC2530 协调器 | 建网、管理入网、串口输出 24 字节定长帧 |
| 网关层 | Ubuntu + C 服务端 | 串口解析、SQLite 落库、告警判定、内置 HTTP 与网页 |
| 上云层 | ESP32-S3 + ESP-IDF | 并联取协调器串口信号，解析后经 Wi-Fi 转 MQTT |

数据走**双链路并行**：串口链路写 `env_data`，MQTT 链路写 `env_data_mqtt`，
口径完全相同，互为交叉验证——两边数值不一致就能立刻定位是哪一段坏了。

控制链路反向贯通：网页按钮 → `/api/cmd` → 手写 MQTT 报文 → ESP32 → 协调器 UART1 → 节点继电器。

关键数据：

- 串口 115200 8-N-1，实测帧间隔 1.000 秒；稳定运行时坏帧 / 残帧 / 重同步 / 库错 / 重连全部为 0
- 网关单进程单线程（epoll 统一事件循环），**230 项离线断言全部通过**，不需要任何硬件
- 服务化后 `kill -9` 3 秒自动拉起（PID 2350 → 3343），`enabled` 开机自启
- 第 4 步：96 帧全部发布、丢弃 0、LWT retained；服务端收到 198 / 入库 198 / 解析失败 0
- 第 5 步：命令命中率 8/8，帧 #432→#905 连续无断档，坏帧率 0.33%，延迟 1~2.6 秒
- 第 6 步：1h→30s 桶 120 点、6h→180s 桶 120 点、24h→900s 桶 96 点；有数据的桶才返回，缺口不补 0

## 技术栈

**嵌入式端**
`C` · `CC2530 (8051)` · `IAR EW8051` · `Z-Stack 2.5.1a` · `OSAL` · `ZigBee / IEEE 802.15.4` · `UART` · `ADC` · `单总线时序`

**网关固件**
`ESP32-S3` · `ESP-IDF v5.5` · `FreeRTOS` · `UART 透传` · `Wi-Fi 状态机与重连` · `MQTT (QoS 1 + 遗嘱消息)`

**服务端**
`Linux` · `C` · `termios` · `epoll` · `signalfd` · `单进程事件循环` · `SQLite (WAL + 批量事务)` · `socket 手写 HTTP` · `中值滤波与自适应基线` · `systemd`

**明确不做**
`低功耗（终端 PM2 休眠）` · `TLS` · `掉线续传本地缓存` · `多节点`
这几项都属于量产/长稳范畴，不影响任何一条链路的正确性，
而本地又没有条件做 24 小时以上验收——做了也拿不出可信数据，所以不写。

## 源码

`code/linux_gateway/` 是第 3 步的完整实现——单进程单线程 C 服务，
termios 串口 + epoll 事件循环 + SQLite WAL 批量提交 + 手写 socket HTTP + 网页编进二进制。
第 5 步的网页远控也在这里（`gw_cmd.c` 手写 MQTT 报文，不依赖 libmosquitto）。
第 6 步的历史曲线同样在这里：`gw_db_trend()` 做 SQL 时间桶聚合，
`/api/trend?range=1h|6h|24h&node=0` 返回点数固定的序列。

`code/esp32_bridge/` 是第 4 步的网关固件——UART 收协调器帧、24 字节定长帧解析、
Wi-Fi 状态机、MQTT 发布（含遗嘱消息）。`tests/` 下有三个串口探针脚本，
用来区分「芯片没电 / 没进下载模式 / 波特率不对」这三种同样报 `No serial data received` 的故障。

```bash
cd code/linux_gateway
make && make test          # 230 项断言，不需要任何硬件
python3 tools/sim_node.py --socat   # 无硬件时用虚拟串口跑通全链路
```

CC2530 那一层（终端节点 / 协调器）的工程骨架基于课程提供的 Z-Stack 示例，
整包公开涉及他人版权，所以没有放进仓库；那部分的关键实现与踩坑写在
第 1、2、6 周的手记里。

## 关于怎么写

两条自己定的规矩：

1. **只写真实发生过的事。** 写错的那几版留着——「为什么错」比「正确做法」有用。
2. **给可以对照的现象和数据。** 帧数、坏帧率、延迟几秒、哪一次是 8/8 命中，而不是一句「效果很好」。
