二、两个模拟量怎么读

光敏和烟雾共用同一个 ADC 模块，靠 ADCCON3 的低 4 位切换通道。 官方写法是这样的（light.c，光敏通道 6）： 

uint16 myApp_ReadLightLevel(void)
{
    uint16 reading;

    /* 使能通道：ADCCFG 的 bit6 对应 P0_6 作模拟输入 */
    ADCCFG |= 0x40;

    /* 写这个寄存器即启动一次转换 */
    ADCCON3 = 0x86;

    /* 等转换完成（bit7 = EOC） */
    while (!(ADCCON1 & 0x80));

    /* 转换完关掉通道 */
    ADCCFG &= (0x40 ^ 0xFF);

    reading = ADCL;
    reading |= (int16)(ADCH << 8);
    reading >>= 8;
    return reading;
}

烟雾模块只差三个地方：

项目光敏（P0_6）烟雾（P0_7）
ADCCFG 掩码0x400x80
ADCCON3 取值0x860x87
通道号（低 4 位）67
!
最容易漏的一步：ADCCFG 必须先置位。
CC2530 的 GPIO 默认是数字模式。ADCCFG 每一位对应 P0 的一个脚， 置 1 才把该脚切换成模拟输入。只写 ADCCON3 而忘了 ADCCFG， 读出来会是一个固定值或跳变噪声，很容易误判成「传感器坏了」。

关于精度

上面这段是官方写法：把 ADCH 左移 8 位后再整体右移 8 位，等价于 只取结果的高 8 位。CC2530 的 ADC 是 12 位，但官方驱动用了 8 位精度， 对光照和烟雾这种趋势量够用。

如果需要 12 位精度，读法应该是 (ADCH << 6) | (ADCL >> 2)—— 但注意 ADCL 的低 2 位是无效位。两种读法不要混用。

参考电压与抽取率

ADCCON3 = 0x86 拆开看：

0x86 = 1000 0110
       ││││ └┴┴┴─ ECH  = 6     通道 6（P0_6）
       ││└┴─────── EDIV = 00    64 抽取率
       └┴───────── EREF = 10    内部参考 AVDD5

EREF=10 表示用 AVDD5（3.3V）做参考。 所以 8 位读数 v 对应的电压约是 v / 255 × 3.3V。 需要更高精度可以改 EREF 到内部 1.25V 基准，或提高抽取率换更稳的值。

三、三条铁律

×
铁律 1：P0_4 / P0_5 / P0_6 / P0_7 绝对不能设成输出。
这四个脚接着传感器。设成输出会：
· P0_4 单总线被强驱，DHT11 再也读不出数据
· P0_6 / P0_7 模拟输入被短路到地，ADC 读数变成 0
· 严重时倒灌电流损坏引脚
!
铁律 2：所有外设的极性要核对，不要凭「通常习惯」猜。
这块板三种极性各不相同：蜂鸣器高电平响、LED 高电平亮、 继电器低电平吸合。搞反了不报错，只是「按了没反应」。
i
铁律 3：P2_1 / P2_2 是调试口，不要占用。
这两个脚接 CC-Debugger。程序里如果把它们复用成普通 IO，会直接导致下载器连不上芯片， 而且下次烧录必须靠复位时序抢时间才能救回来。

四、推荐的初始化顺序

顺序不是随便排的。蜂鸣器那个坑决定了它必须排在最前面： 

void main(void)
{
    clock_init();      /* 1. 时钟，后面所有时序都依赖它 */
    beeper_init();     /* 2. ★ 蜂鸣器静音，必须尽早 */
    uart0_init();      /* 3. 串口，方便后面打调试信息 */
    led_init();        /* 4. LED 全灭 */
    sensor_init();     /* 5. 传感器脚设成输入，配 ADCCFG */
    relay_init();      /* 6. 继电器断开，避免上电误动作 */
}

每一步的理由：

  • 时钟第一：DHT11 时序要求微秒级精度，时钟不对后面全乱
  • 蜂鸣器第二：复位后弱上拉会让它长鸣，越早拉低越好
  • 串口第三：后面每一步都能打日志，出问题好定位
  • 继电器最后：上电瞬间 GPIO 状态不确定，先确保它处于断开状态，防止带着负载上电

五、为什么之前那份表是错的

最早我手上只有原理图 PDF，就用工具提取里面的网络标号，整理出一份引脚表。 结果是：

功能从 PDF 提取（错）源码实际（对）
蜂鸣器P0_6P0_0
人体红外P0_4P0_5
光敏P1_1P0_6
MQ-2P0_0P0_7
继电器P0_5P1_3

五个全错，而且是「错位式」的错——看起来像是整体串了一位。

错在哪

原理图是分块画的，同一个网络标号会在多个区域出现（MCU 符号旁、连接器旁、传感器模块旁）。 自动提取时按出现顺序配对，一旦某个区域多一个或少一个标号，后面全部错位。

更麻烦的是，这种错误不会立刻暴露：把蜂鸣器写成 P0_6，代码能编译、能烧录、 板子也不报错，只是「改完没效果」。你会怀疑极性、怀疑电路、怀疑代码， 但很难怀疑到「表本身就是错的」这一层。

正确的验证方法

三条，按可靠性排序：

  1. 能跑的源码 > 原理图导出物。源码里 #define BEEP_PIN P0_0 是编译过、烧录过、验证过的事实
  2. 手册寄存器表 > 猜。CC2530 datasheet 里有每个脚的复用功能表
  3. 实测最可靠：写个程序把某个脚设成输出翻转，用万用表量对应器件有没有反应

原理图描述「设计意图」，源码描述「实际能工作的东西」。
两者冲突时，后者赢。
