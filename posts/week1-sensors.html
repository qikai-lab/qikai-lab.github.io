第 1 周：五个传感器全部打通

2026-10-23 · 第 1 步已通过 ADC 单总线 排障复盘

第 0 周解决的是「代码能不能烧进板子」，第 1 周解决的是「烧进去的代码能不能读对数据」。 目标是五路传感器——温湿度、光照、烟雾、人体红外、继电器——全部读通，同时显示在 1.44 寸彩屏上、同时从串口打印。

DHT11 和人体红外一天就通了，唯独 ADC 那两路花了整整一天，而且我连续改错了三次。 三次都以为自己找到了根因，三次都被实测数据打回来。这篇把三次弯路完整写下来， 因为最后那个真因，如果不是被数据逼到死角，根本想不到。

✓
最终结果：五路全部读通。串口 115200 每秒输出 T=21.5C H=46.0%RH | light=0713/69% gas=0003 | human=0 relay=OFF， 彩屏三行数据同步刷新，继电器由板载 S1 按键手动控制，屏幕状态与实物一致。

传感器引脚实测读数结论
DHT11 温湿度P0_4 单总线21.5°C / 46%RH通过
光敏电阻P0_6 / ADC ch60713（69%）通过，随光变化

上电自检会打印一行「探针判据」，这一行是后面所有排障的地基： 

SCAN  c15=0342  c14=0064  c7=0003  c6=0713  c5=1023  c4=0994  c1=0984  c0=0064
SCAN  VDD/3 = 0342  OK -> ADC core + AVDD5 reference verified
SCAN  pin probe: c0(beep)=0064 c1(key,pull-up)=0984  OK -> ECH really selects PINS

二、ADC 三次改错，一次比一次接近

CC2530 的 ADC 用起来只有三个寄存器：ADCCON1、ADCCON2、ADCCON3。 写 ADCCON3 就立即启动一次转换，没有单独的启动位。 看起来简单，但位域定义只要错一位，现象就完全变样。

第 1 次：结果寄存器取位错

初始代码写的是 ADCL | ((ADCH & 0x03) << 8)，只取 ADCH 的低 2 位。 现象是读数在四个桶里乱跳：0~255、256~511、512~767、768~1023， 导致烟雾值偶尔冲高，蜂鸣器莫名报警。

查手册才发现：ADCL 的 bit7:2 才是 ADC[5:0]，bit1:0 是未使用的， ADCH 的 bit7:0 是 ADC[13:6]。所以拼起来得到的是 16 位结果左移 2 位， 正确做法是拼完再右移 5 位： 

v  = (unsigned int)ADCL;
v |= (unsigned int)((unsigned int)ADCH << 8);
v >>= 5;              /* 不是 >>4，ADC[13:6] 有 8 位 */

这一步改完，乱跳消失了。但读数变成了恒定值——于是有了第二次改错。

第 2 次：把 ADC 自己占死了

现象很奇怪：light 恒为 0130、gas 恒为 0687，连读 16 次一个数都不动。

当时的思路是「可能 ADC 没真正启动」，于是把 ADCCON1 写成 0x70 想手动置 ST 位， 又把 ADCCON2 设成 0x3F。结果更死。

查英文手册（SWRU191 P130）才明白两件事：

  • ADCCON1 的复位值 0x33 本来就是对的：bit7 EOC、bit6 ST、bit5:4 STSEL、bit3:2 RCTRL、bit1:0 保留为 11。写 0x70 反而把 ST 置了位。
  • ADCCON2 的低 4 位是 SCH，写 0x3F 让 SCH=1111，选中的是 VDD/3 内部通道，ADC 被内部通道占死，跟引脚彻底无关了。
!
这里还埋了一个错误判据：我曾经用「同一通道连读 16 次，spread < 15 就说明 ADC 在正常转换」来判断。 这是错的——读到的如果是同一个旧值，spread 照样是 0。 「数值稳定」既可能是转换正常，也可能根本没在转换。

第 3 次：ECH 是 4 位，不是 3 位

把 ADCCON1 改回 0x33、ADCCON2 改回 0x00、 移位改成 >>5 之后，读数还是不动。 但这次自检里出现了一行我没在意的数据：c15=0342。

0342 恰好等于 1023 × 1.1 / 3.3 ≈ 341——内部 1.1V 基准除以 AVDD5。看起来「基准是对的」。 问题是我当时用的基值是 0xB8： 

ADCCON3 = 0xB8 | ch;
/* 0xB8 = 1011 1000
   bit7:6 EREF = 10  -> AVDD5 基准
   bit5:4 EDIV = 11  -> 512 抽取
   bit3:0 ECH  = 1000  <- 这里！
   ch 或进去之后 ECH = 8 + ch，选的是【内部通道】而不是 AIN */

ECH 是 4 位（bit3:0），不是 3 位。0xB8 的 bit3 恰好是 1， 于是 0xB8 | 6 = 0xBE，ECH=1110 → 选中片内温度传感器，固定输出 0064； 0xB8 | 7 = 0xBF，ECH=1111 → 选中 VDD/3，固定输出 0342。

这也解释了为什么 c15=0342 和 c7=0342 永远相等—— 它俩本来就是同一个通道，是自己跟自己比，这个「基准校验」从头到尾都是假通过。

✕
铁证：c1 应该是 1023，实测 0020。 AIN1 接的是 P0_1 按键，内部 20k 上拉，读数必然贴着满量程。 读到 0020 说明选的根本不是 AIN1，而是 AIN2-AIN3 差分通道。 这一对数一出，前面所有猜测全部作废。

正确写法是把基值改成 0xB0（bit3 必须为 0）：

#define ADC_ADCCON3_BASE  0xB0U   /* EREF=10 AVDD5, EDIV=11 512x, ECH 低 4 位留 0 */

ADCCON3 = (unsigned char)(ADC_ADCCON3_BASE | (ch & 0x0FU));
while ((ADCCON1 & 0x80U) == 0) { /* 等 EOC */ }

改完之后 c1=0984，和理论值 1023 只差 ADC 输入阻抗分压的那一点，全通。

怎么一眼确认「真的在采引脚」

探针法比看数值可靠。选两个极性相反的引脚做对照：

探针通道物理状态应该是
c0AIN0 = P0_0 蜂鸣器输出低电平接近 0000
c1AIN1 = P0_1 按键上拉20k 上拉到 3.3V接近 1023

只要 c1 > 900 且 c0 明显偏小，就说明 ECH 真的选到了引脚。 这两个数不对，后面所有读数都不可信。

三、光敏：raw 变大到底算亮还是算暗

这路的问题不在代码，在物理接法。光敏插在 P8 二针排针上， 原理图里 1 脚接 VCC3.3、2 脚接 P0_6，P0_6 再经 R14 10k 下拉到地。 

VCC3.3 ── LDR ──┬── P0_6 ── ADC
                └── R14 10k ── GND

V   = 3.3 × 10k / (R + 10k)
raw = 1023 × 10 / (R + 10)
R   = 10230 / raw - 10   (kΩ)

光越强 → R 越小 → raw 越大。但这个公式只在「光敏在上臂」时成立。 如果实物是反过来（光敏在下臂），同一个 raw 换算出的阻值会差一个数量级：

假设raw=757（室内）raw=206（手掌遮住）raw=958（手电照）是否自洽
LDR 在 3V3 侧3.5k39.6k0.68k遮住变暗、阻值变大 ✓
LDR 在 GND 侧28.5k2.5k68k遮住反而阻值变小 ✗

只有第一行符合物理规律。所以确认是上臂，屏幕上的亮度百分比方向是对的。

顺带把屏幕显示从 raw 改成了 0~100 的相对亮度。原来的 LGT:0790 容易被误当成电阻值——它只是 ADC 原始值，没有单位也没有方向。

四、继电器：极性反了，屏幕跟实物对着干

现象很好笑：屏幕上写着 RLY:OFF，手摸继电器却是吸合的。 反过来按一下，屏幕 RLY:ON，实物却断开了。

原因是照抄了官方例程的宏定义，假设「低电平吸合」。实测这块板是高电平吸合。 官方 3.继电器模块/main.c 更坑：文件头注释写「高电平断开」， 正文代码里 RELY=1 那一行注释却是「吸合」——文档自相矛盾。

结论：注释打架的时候，以实测为准。BSP_RELAY_ACTIVE_LOW 改成 0，一行解决。

另外把继电器从「跟着人体红外自动跳」改成了「S1 按键手动翻转」。 官方按键代码是 while(!KEY1); 死等松手，会把整个主循环卡住； 改成非阻塞状态机：每 10ms 采一次，连续 3 次一致才认账，只在下降沿触发。

五、MQ-2：不是坏了，是没烧够温度

烟雾一路读数长期是 0003，反算阻值： 

Rs = 1550 / raw - 1  (kΩ)
raw = 3   ->  Rs ≈ 515k
raw = 11  ->  Rs ≈ 140k

正常洁净空气下 MQ-2 的 Rs 是 5k~20k（raw 70~150）。515k 差了整整一个数量级。 一开始我的判断是「加热丝没通电」，但手背碰金属网罩是温的—— 如果加热丝断了，会是完全冰凉。所以这个判断是错的。

决定性实验是对着网罩哈一口气：raw 从 0003 跳到 0011，Rs 从 515k 掉到 140k， 响应了 3.7 倍。同一时间湿度从 46%RH 涨到 58%RH，温度也升了 0.4°C。 三路传感器同时朝同一个物理事件变化，说明链路是通的。

i
结论：加热丝通、测量电极通、气敏层有响应。 气敏层要 300°C 才充分导通，现在大概只到 150~200°C（加热电压约 3.3~4V，不是 5V）， 所以 Rs 底噪高一个数量级。元件没坏，是加热功率不足。

板载分压是 1k 负载，raw 的理论上限约 0775（Rs→0 时）。 这意味着最初设的报警阈值 700 在这块板上永远达不到—— 这个坑留到第 5 步做告警功能时再解决，正确做法是改成「基线 + 增量」而不是绝对阈值。

六、五条写下来的排障口诀

  1. 数值固定不动，先怀疑寄存器状态，不要怀疑传感器。这一轮三个 bug 全部来自位域写错。
  2. 位域一定查英文手册。中文版 ADCCON3 那张表排版错乱，丢了 ECONV 位、位宽也错。
  3. 别用「自己跟自己比」做自检。0xB8|15 和 0xB8|7 都是 0xBF，永远「通过」。
  4. 有可运行的官方源码时，信源码不信原理图。原理图 PDF 提文本会丢连接关系，本项目因此把上拉判断错过一次。
  5. 注释和代码打架时，信实测。继电器极性就是靠「屏幕 OFF 但实物吸合」这个矛盾发现的。
