ZigBee 无线环境监测系统

电池供电的传感器节点采集温湿度、烟雾、光照与人体感应，经 ZigBee 协调器汇聚， 串口送进 Ubuntu 上的 C 网关：落库、出曲线、判定烟雾告警、网页远程控制继电器； 另一路经 ESP32-S3 转成 MQTT 上云。两条链路并行、互为交叉验证。

二、演示视频

手机竖拍，无剪辑

全链路实机演示 72 秒 · 一镜到底

从三块板子上电开始，一直走到浏览器里出现曲线。中间没有剪辑、没有换镜头， 拍的就是实际接好线、实际跑起来的样子——包括屏幕上"没有信号"时那一段。

  • 00:00协调器上电，彩屏亮起，串口开始往外吐帧
  • 00:09P0_3 飞线接进 ESP32 的 GPIO18，同一路信号同时喂给板载 CH340
  • 00:18ESP32-S3 上电，OLED 显示 IP 与帧计数，WiFi 连上后开始 MQTT 发布
  • 00:27终端里跑起网关程序，每帧解析完立即入库
  • 00:45浏览器打开 8080，五张实时卡片开始跳数
  • 00:55切到历史曲线，1 小时 / 24 小时来回换，鼠标悬停读出该点温湿度
历史曲线：1 小时 / 24 小时切换 + 点选读数 曲线按真实时间轴画，掉线处断开不连线；鼠标悬停显示该点温湿度
网页远控：点按钮，继电器吸合 从浏览器点击到节点上"咔"一声，整条反向链路走通
终端侧：命令下发的完整日志 网关收到请求、发 MQTT、ESP32 转 UART、协调器广播、节点动作

四、连线图

核心只有一处：P0_3 分两路

最容易搞错的一点：ESP32 不是串在 Ubuntu 前面的中间环节。 协调器同一个 P0_3 脚同时喂两路——一路给板载 CH340 进电脑，一路飞线给 ESP32。 这是两条并联的链路，各自独立，互为交叉验证。

串口链路（网页的数据来源） MQTT 链路（旁路，交叉验证） 内部传递（不经过任何线）

实际要接的只有三根线

协调器 P4 排针 → ESP32
协调器 方向 ESP32-S3 作用 接错会怎样
P0_3 → GPIO18 上行数据（24 字节帧） 没数据，字节=0
P0_5 ← GPIO17 下行命令（继电器开关） 远控点了没反应，日志报「发送成功」但节点不动
GND — GND 共地 最容易忘的一根，表现为数据乱码或完全没有
!
下行是 P0_5，不是 P0_2，也不是 P0_4。 协调器源码里 UART1 配在「备用位置 1」（PERCFG.U1CFG=0），这个位置是高脚收： RX = P0_5、TX = P0_4，与 UART0（低脚收：RX=P0_2 / TX=P0_3）正好相反。 接 P0_4 等于接到协调器自己的发送脚上，一个字节都收不到； 接 P0_2 会撞上板载 CH340 的 TXD。
